# LUNA

LUNA — статическое веб-приложение на GitHub Pages. Клиентская часть находится в `index.html`, использует модульный Firebase Web SDK с CDN. Firebase-проект приложения — `luna-a9fa5`; конфигурация клиента не содержит серверных секретов. Серверная логика в проекте не используется.

## Текущее устройство

- Вход: Firebase Authentication, Email/Password; создание постов и комментариев требует подтверждённой почты.
- Данные: Cloud Firestore, база по умолчанию; серверной логики в проекте нет.
- Публикация сайта: GitHub Actions из `main` (см. `.github/workflows/pages.yml`).
- Цикл: начало хранится только в `localStorage`; в Firebase не отправляется.

## Коллекции Firestore

| Коллекция | Назначение и доступ |
| --- | --- |
| `lunaProfiles/{uid}` | Безопасная карточка профиля; по умолчанию приватная (владелица и подруги), публичность можно включить в настройках |
| `lunaPrivateProfiles/{uid}` | Настроение и любимое; доступ только владелице |
| `lunaUsernames/{nickLower}` | Точный поиск ника для вошедших участниц; только UID и публичный ник |
| `lunaFriendRequests/{fromUid~toUid}`, `lunaFriends/{friendshipId}` | Заявки и подтверждённые дружеские связи; операции ограничены участницами |
| `lunaChats/{chatId}/messages/{messageId}` | Личные сообщения только между подругами; ограниченные реакции, ответы и фото |
| `lunaChats/{chatId}/receipts/{uid}`, `typing/{uid}` | Статус прочтения и печати участницы личного чата |
| `lunaRooms/{roomId}` и `messages`, `receipts`, `typing`, `lunaRoomInvites/{roomId~uid}` | Группы, каналы, сообщения, статусы и приглашения с проверкой членства и прав |
| `lunaFriendRequestLimits/{uid}`, `lunaPostLimits/{uid}` | Приватные лимиты отправки заявок и публикаций |
| `posts/{postId}` | Общая лента; только безопасные публичные поля, без UID автора |
| `posts/{postId}/likes/{uid}`, `comments/{commentId}` | Лайки по одному документу на UID; комментарии с авторством и лимитом длины |
| `postOwners/{postId}` | Закрытая связь записи с UID автора; только автор и модератор с trusted claim |
| `userPostIndex/{uid}/posts/{postId}` | Приватный индекс записей, читаемый только владелицей |
| `lunaAgeConsents/{uid}`, `lunaBlocks/{uid}/users/{blockedUid}` | Подтверждение 14+ и личный блок-лист |
| `reports/{reportId}`, `lunaBans/{uid}`, `moderationSettings/contentFilter` | Жалобы, баны и настройки фильтра; модерация только по trusted `admin` claim |
| `lunaAccountDeletionRequests/{uid}` | Запрос на удаление с административным следом |

Неописанные коллекции и операции запрещены по умолчанию. Почта хранится в Firebase Authentication; цикл остаётся в браузере. Старые документы `lunaPosts` остаются нетронутыми, но не участвуют в новой ленте. Ранние черновики из прежней вкладки существовали только в памяти браузера и не переносятся.

## Общая лента «Девичник»

- Записи в `posts/{postId}`: текст до 2 000 символов, категория, время, безопасные поля автора, до 10 хэштегов, флаги анонимности/удаления/скрытия и счётчики. У неанонимного поста есть UID автора для блокировок; у анонимного UID отсутствует. UID — открытый идентификатор Firebase, не email.
- Закрытая привязка `postOwners/{postId}` содержит UID и флаг анонимности. Читать конкретную привязку могут её автор и аккаунты с доверенным Firebase Auth claim `moderator: true` или `admin: true`; список привязок запрещён. Custom claim может выдавать только доверенный Admin SDK-код, не клиент сайта. В текущем проекте авторизованные модераторы ещё не настроены.
- Лайки: `posts/{postId}/likes/{uid}`; путь UID обеспечивает один лайк участницы на запись. Счётчик меняется в той же транзакции.
- Комментарии: `posts/{postId}/comments/{commentId}`, максимум 1 200 символов. Удалить комментарий может только его автор. Счётчик защищён событием комментария, проверяемым совместно с записью/удалением.
- Записи требуют подтверждённой почты и используют имеющийся лимит 10 публикаций за часовое окно. Создание поста, закрытой записи автора и события лимита происходит атомарно.
- Удаление поста — закрытие с очисткой текста, хэштегов и публичного имени (soft delete). Firestore не удаляет вложенные коллекции автоматически, поэтому лайки/комментарии остаются закрытыми и привязка сохраняется только для аудита; документ пропускается интерфейсом. Старые документы `lunaPosts` не удаляются, но новая лента их не читает.
- Лента слушает последние 20 документов через `onSnapshot`; кнопка подгружает следующие 20 через `startAfter`. Комментарии подгружаются отдельно и показывают последние 20.
- Для фильтрации используются категории и хэштеги в нижнем регистре; комбинации фильтров требуют составных индексов из `firestore.indexes.json`. При изменении выборки Firebase может попросить время на сборку индекса.

## Допущения и ограничения этапа 2

- Анонимность скрывает имя, фото и UID от обычных участниц; текст поста всё равно может сам содержать личные данные, поэтому автору нужно проверить его перед публикацией.
- Для просмотра авторства модерации нужен доверенный custom claim `moderator: true`. Без серверной части в этом статическом сайте безопасно назначать его нельзя.
- Режим анонимного комментария не добавлен: анонимность относится только к исходной публикации.
- Фото профиля поста отображается для подписанного автора как безопасное публичное поле; email, настроение и цикл в посты не копируются.

## Публикация правил и индексов

Из корня репозитория:

```sh
npm install --global firebase-tools
firebase login
firebase deploy --only firestore
```

Файл `.firebaserc` выбирает `luna-a9fa5`, а `firebase.json` направляет Firebase CLI на `firestore.rules` и составные индексы из `firestore.indexes.json`. Команда `firebase deploy --only firestore` отправляет оба Firestore-ресурса (правила и индексы), но не публикует сайт. Перед публикацией проверь в Firebase Console, что выбран проект **Luna (luna-a9fa5)** и база **default**. Деплой правил не публикует сайт и не меняет документы.

## Известные ограничения

- Лимит заявок/постов привязан к часовому окну от первого события, а не к скользящим 60 минутам; на границе окон возможен короткий burst.
- Сообщения ограничены по размеру, но отдельного лимита частоты сообщений пока нет.
- В текущей сессии нет доступного Firebase CLI и инструментов управления Firebase Console. Поэтому опубликованное состояние проекта и успешность деплоя не подтверждены; файл правил нужно отправить командой выше из авторизованного окружения.

- Интерфейс назначения администраторок комнаты пока отсутствует. Правила позволяют создательнице безопасно обновлять список администраторок, а публиковать в канале могут только участницы из этого списка или сама создательница.


## Этап 3: модерация и защита (черновая реализация)

- Регистрация требует явный чекбокс 14+ и принятие правил. Для существующих аккаунтов в профиле появляется отдельное подтверждение. Создание постов, комментариев, заявок и блокировок требует подтверждённой почты и документа `lunaAgeConsents/{uid}`.
- Профиль по умолчанию приватный. Публичную карточку видят вошедшие участницы, приватную — владелица и подруги; email, настроение и любимое остаются приватными.
- Жалобы в `reports` содержат тип объекта, цель, причину и краткий снимок. Только автор жалобы и аккаунт с Firebase custom claim `admin: true` читают их. Админ-панель скрывает посты, комментарии и сообщения, блокирует UID автора и закрывает жалобу. Claim выдаётся только доверенным Admin SDK вне клиентского сайта.
- Блок-лист хранится в `lunaBlocks/{uid}/users`. Он скрывает обычные посты/комментарии/сообщения в интерфейсе, запрещает новые заявки и закрывает личный чат в правилах. Сообщения общей группы можно скрыть в интерфейсе, но запретить отправку каждому заблокировавшему участнику без серверной проверки состава комнаты нельзя.
- Фильтр запрещённых слов настраивается администратором в `moderationSettings/contentFilter`. Проверка слов и ссылок выполняется в браузере и обходится прямым Firebase API; для строгого enforcement нужна доверенная серверная функция.
- Скрытые посты всё ещё доступны через прямой Firestore запрос: общий запрос ленты читает и старые записи без `isHidden`, чтобы не сломать старые данные. Для серверного скрытия требуется миграция старых постов и фильтрованный запрос перед публикацией.
- JSON-выгрузка содержит доступные профиль и приватные поля, дружбу/заявки, блокировки, посты/комментарии, до 100 последних сообщений каждого личного чата и каждой комнаты участницы, а также локальную дату цикла.
- Удаление требует повторного ввода пароля и подтверждённую почту, создаёт `lunaAccountDeletionRequests/{uid}`, удаляет Auth-пользователя, профиль, ник, приватный профиль и локальные данные, а собственные посты очищает. Запрос разрешён и заблокированной участнице. Вложенные сообщения/комнаты, заявки дружбы, закрытые связи авторов и жалобы клиент каскадно не удаляет; нужна доверенная функция или ручная административная очистка. Заявка сама по себе не очищает остаточные данные автоматически.
- «Правила сообщества» и «Политика конфиденциальности» — русские черновики с незаполненным контактом владельца; перед публичным запуском нужны проверка владельцем и юристом.

### Ограничения проверки этапа 3

- Firebase CLI/эмулятор и API консоли недоступны в этой среде. Новые правила не скомпилированы и не опубликованы. До деплоя проверь их в Firebase Rules Emulator: подтверждение возраста, блокировки и admin claim меняют доступ к действующим операциям.
- `admin: true` должен выставляться только владельцем проекта через доверенный Admin SDK. В интерфейсе назначение администраторов отсутствует.
- Выполнена только статическая проверка JavaScript. Живые тесты Auth/Firestore и GitHub Pages не запускались.


### Назначение администратора

Админ-панель открывается только при наличии Auth custom claim `admin: true`. Не добавляй claim в код клиента и не храни service account key в репозитории. В доверенной Google Cloud Shell/Firebase Admin SDK-сессии установи `firebase-admin`, проверь выбранный проект `luna-a9fa5`, найди UID нужной учётной записи и выполни от имени владельца проекта:

```js
const admin = require('firebase-admin');
admin.initializeApp({ projectId: 'luna-a9fa5' });
const uid = 'UID_НУЖНОЙ_УЧЁТНОЙ_ЗАПИСИ';
const user = await admin.auth().getUser(uid);
await admin.auth().setCustomUserClaims(uid, { ...(user.customClaims || {}), admin: true });
```

После установки claim выйди и войди снова (или принудительно обнови ID token), затем открой пункт «Модерация». Проверяй UID особенно внимательно: это полномочие позволяет читать жалобы и блокировать аккаунты.

## Этап 4 — поиск и сообщества

- Поиск никнеймов использует нормализованный prefix-запрос (`nickLower`, до 20 результатов). В `lunaUsernames` хранятся только UID и публичный ник; email и приватные поля не выдаются.
- Рекомендации собираются из общих подруг и совпадений по интересам только для профилей, которые правила разрешают читать. Связи второго круга хранятся в `lunaFriendEdges/{uid}/connections/{friendUid}`. Они видны самой участнице; её подруги могут читать их, только если владелица сделала профиль публичным и включила отдельный приватный переключатель рекомендаций. Существующие связи дополняются при входе; для полного графа подругам нужно хотя бы раз войти с обновлённой версией.
- Публичная карточка профиля включает аватар, описание, интересы, дружеские действия и публичный счётчик `friendCount`. При принятии заявки счётчик принимающей стороны обновляется в транзакции; при следующем входе отправительница сверяет свой счётчик со списком дружбы. Это сводная цифра, не список контактов.
- Приватный профиль хранит `presenceEnabled`; при согласии клиент обновляет `lunaPresence/{uid}.lastSeen` каждые 45 секунд и удаляет документ при выключении. Статус «онлайн» — best effort; закрытая вкладка или потеря сети может задержать обновление. Для достоверного `onDisconnect` потребуется Realtime Database и настройка Firebase Presence.
- Сообщества хранятся отдельно в `lunaInterestCommunities/{communityId}`, членство и роль — во вложенной `members/{uid}`, лента — во вложенной `posts/{postId}`. Создание атомарно создаёт сообщество и владелицу; участница вступает только под собственным UID; только владелица меняет роли. Удаление сообщества из интерфейса не добавлено, чтобы не оставлять orphan-данные; для полного удаления вложенных публикаций нужен отдельный механизм.
- Лимит публикаций 10 в час общий для общей ленты и сообществ. Сообщества загружаются первыми 50 документами, лента — последними 30; пагинация и выход из сообщества пока не добавлены.

Новые правила и клиентский код добавлены в черновой PR. Публикация Firebase Rules и сайта не выполнялась. Перед публикацией проверь правила через Firebase Emulator/Rules Playground на проекте `luna-a9fa5`; затем опубликуй правила и обнови GitHub Pages отдельно.
## Этап 5 — улучшение чатов

- В личных чатах и комнатах каждое сообщение показывает «Отправлено»; у личных чатов оно сменяется на «Прочитано» после отметки получательницы. В группе/канале отметка прочтения становится «Прочитано», когда хотя бы одна другая участница открыла комнату.
- Отметка чтения хранится отдельным документом `lunaChats/{chatId}/receipts/{uid}` или `lunaRooms/{roomId}/receipts/{uid}`. Участница может менять только свой документ; в комнате прочитать отметки могут только её участницы. Индикатор «печатает…» хранится отдельно, доступен только участницам, автоматически гаснет через 4 секунды и не отображает просроченное состояние.
- Ответы сохраняют короткую цитату (до 150 символов), не копируя фото/стикер. Реакции хранятся в сообщении по UID: правила допускают менять только собственное значение и ограничивают словарь эмодзи и размер карты до 100. Удалить сообщение может только его автор.
- Фото сжимаются в браузере до максимальной стороны 800 px, JPEG, строка Data URL до 275 000 символов (примерно 200 КБ изображения). Firebase Storage в этом проекте не подключён; файл остаётся внутри сообщения Firestore. Правило Firestore принимает только JPEG Data URL до 280 000 символов. Существующие старые фотографии не переписываются.
- На вкладке «Чаты» отображается суммарный счётчик непрочитанных (с ограничением проверки 100 сообщений на беседу). Поиск фильтрует список по названию и последнему превью. Закрепления хранятся в `localStorage` отдельно на этом устройстве и для каждого аккаунта; другие устройства их не синхронизируют.
- Стикеры загружаются из `assets/stickers/`: добавлены 12 простых локальных SVG. Новые сообщения используют только локальные наборы; старые Tenor/Giphy-ссылки продолжают отображаться, если источник доступен. Удалённая загрузка Tenor для новых стикеров сейчас не включена.

### Проверка и ограничения этапа 5

- Правила проверены вручную на явную проверку членства, идентичность UID, типы и размеры полей, разделение create/update/delete и запрет менять чужие реакции/отметки. Ограничены списки сообщений 100 документами, индикаторы печати 20 документами, отметки чтения комнаты — 50 документами.
- В этой среде нет подключённого Firebase Console/CLI API, а Firebase CLI и Rules Emulator не доступны. Правила не компилировались эмулятором и не публиковались в `luna-a9fa5`; перед публикацией проверь Firestore Rules Emulator/Playground, особенно чтение `receipts`, реакцию на старом сообщении без поля `reactions` и удаление собственных сообщений. GitHub Pages не публиковался.
- Пересчёт непрочитанных выполняется при открытии/обновлении списка чатов и при получении новых сообщений в открытом чате. Для обновления счётчика, пока открыта другая страница приложения, вернись на вкладку «Чаты» или перезагрузи список.
- Мягкое удаление модерацией по-прежнему отдельная операция; обычная авторка может удалить только своё сообщение. В группе статусы показывают прочтение хотя бы одной участницей, без списка прочитавших.
