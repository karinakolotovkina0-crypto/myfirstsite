# LUNA

LUNA — статическое веб-приложение на GitHub Pages. Клиентская часть находится в `index.html`, использует модульный Firebase Web SDK с CDN. Firebase-проект приложения — `luna-a9fa5`; конфигурация клиента не содержит серверных секретов. Серверная логика в проекте не используется.

## Текущее устройство

- Вход: Firebase Authentication, Email/Password; создание постов и комментариев требует подтверждённой почты.
- Данные: Cloud Firestore, база по умолчанию; серверной логики в проекте нет.
- Публикация сайта: GitHub Actions из `main` (см. `.github/workflows/pages.yml`).
- Цикл: начало хранится только в `localStorage`; в Firebase не отправляется.

## Коллекции Firestore

| Коллекция | Назначение и доступ |
| --- | --- |
| `lunaProfiles/{uid}` | Безопасная карточка профиля; чтение подругами по правилам, изменение владелицей |
| `lunaPrivateProfiles/{uid}` | Настроение и любимое; доступ только владелице |
| `lunaUsernames/{nickLower}` | Точный поиск ника для вошедших участниц; только UID и публичный ник |
| `lunaFriendRequests/{fromUid~toUid}`, `lunaFriends/{friendshipId}` | Заявки и подтверждённые дружеские связи; операции ограничены участницами |
| `lunaChats/{chatId}/messages/{messageId}` | Личные сообщения только между подругами |
| `lunaRooms/{roomId}` и `messages`, `lunaRoomInvites/{roomId~uid}` | Группы, каналы, сообщения и приглашения с проверкой членства и прав |
| `lunaFriendRequestLimits/{uid}`, `lunaPostLimits/{uid}` | Приватные лимиты отправки заявок и публикаций |
| `posts/{postId}` | Общая лента; только безопасные публичные поля, без UID автора |
| `posts/{postId}/likes/{uid}`, `comments/{commentId}` | Лайки по одному документу на UID; комментарии с авторством и лимитом длины |
| `postOwners/{postId}` | Закрытая связь записи с UID автора; только автор и модератор с trusted claim |
| `userPostIndex/{uid}/posts/{postId}` | Приватный индекс записей, читаемый только владелицей |

Неописанные коллекции и операции запрещены по умолчанию. Почта хранится в Firebase Authentication; цикл остаётся в браузере. Старые документы `lunaPosts` остаются нетронутыми, но не участвуют в новой ленте. Ранние черновики из прежней вкладки существовали только в памяти браузера и не переносятся.

## Общая лента «Девичник»

- Публичные записи хранятся в `posts/{postId}`: текст до 2 000 символов, категория, время, безопасное имя/фото автора, до 10 извлечённых хэштегов, флаги анонимности/удаления, счётчики лайков и комментариев. Документ никогда не содержит UID автора.
- Закрытая привязка `postOwners/{postId}` содержит UID и флаг анонимности. Читать конкретную привязку могут её автор и аккаунты с доверенным Firebase Auth custom claim `moderator: true`; список привязок запрещён. Custom claim может выдавать только доверенный Admin SDK-код, не клиент сайта. В текущем проекте авторизованные модераторы ещё не настроены.
- Лайки: `posts/{postId}/likes/{uid}`; путь UID обеспечивает один лайк участницы на запись. Счётчик меняется в той же транзакции.
- Комментарии: `posts/{postId}/comments/{commentId}`, максимум 1 200 символов. Удалить комментарий может только его автор. Счётчик защищён событием комментария, проверяемым совместно с записью/удалением.
- Записи требуют подтверждённой почты и используют имеющийся лимит 10 публикаций за часовое окно. Создание поста, закрытой записи автора и события лимита происходит атомарно.
- Удаление поста — закрытие с очисткой текста, хэштегов и публичного имени (soft delete). Firestore не удаляет вложенные коллекции автоматически, поэтому лайки/комментарии остаются закрытыми и привязка сохраняется только для аудита; документ пропускается интерфейсом. Старые документы `lunaPosts` не удаляются, но новая лента их не читает.
- Лента слушает последние 20 документов через `onSnapshot`; кнопка подгружает следующие 20 через `startAfter`. Комментарии подгружаются отдельно и показывают последние 20.
- Для фильтрации используются категории и хэштеги в нижнем регистре; комбинации фильтров требуют составных индексов из `firestore.indexes.json`. При изменении выборки Firebase может попросить время на сборку индекса.

## Допущения и ограничения этапа 2

- Анонимность скрывает имя, фото и UID от обычных участниц; текст поста всё равно может сам содержать личные данные, поэтому автору нужно проверить его перед публикацией.
- Для просмотра авторства модерации нужен доверенный custom claim `moderator: true`. Без серверной части в этом статическом сайте безопасно назначать его нельзя.
- Режим анонимного комментария не добавлен: анонимность относится только к исходной публикации.
- Фото профиля поста отображается для подписанного автора как безопасное публичное поле; email, настроение и цикл в посты не копируются.

## Публикация правил

Из корня репозитория:

```sh
npm install --global firebase-tools
firebase login
firebase deploy --only firestore:rules
```

Файл `.firebaserc` выбирает `luna-a9fa5`, а `firebase.json` направляет Firebase CLI на `firestore.rules` и составные индексы из `firestore.indexes.json`. Перед публикацией проверь в Firebase Console, что выбран проект **Luna (luna-a9fa5)** и база **default**. Деплой правил не публикует сайт и не меняет документы.

## Известные ограничения

- Лимит заявок/постов привязан к часовому окну от первого события, а не к скользящим 60 минутам; на границе окон возможен короткий burst.
- Сообщения ограничены по размеру, но отдельного лимита частоты сообщений пока нет.
- В текущей сессии нет доступного Firebase CLI и инструментов управления Firebase Console. Поэтому опубликованное состояние проекта и успешность деплоя не подтверждены; файл правил нужно отправить командой выше из авторизованного окружения.

- Интерфейс назначения администраторок комнаты пока отсутствует. Правила позволяют создательнице безопасно обновлять список администраторок, а публиковать в канале могут только участницы из этого списка или сама создательница.
